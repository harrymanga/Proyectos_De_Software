# ADR-001 — Arquitectura híbrida núcleo + plugins

## Contexto

Se desea crear un "MOD MAKER" multijuego que permita crear, editar y gestionar mods de videojuegos, inicialmente para Factorio. Se evaluaron tres opciones:

- **Opción A (multijuego unificado):** una sola herramienta que soporte todos los juegos por igual. Cada juego usa motores, formatos de archivo, cifrado y estructuras de directorio distintos. No es viable como MVP.
- **Opción B (por grupos de juegos similares):** núcleo común reutilizable + plugins por motor o grupo de juegos. Viable y mantenible.
- **Opción C (por juego individual):** una herramienta por juego. Alto esfuerzo acumulado y duplicación de código.

## Problema

Cómo diseñar una arquitectura que permita soporte para múltiples juegos sin convertir la herramienta en un "God Object" inmanejable, y que sea extensible para futuros juegos.

## Opciones consideradas

1. Multijuego unificado (rechazado: inviable técnicamente como MVP).
2. Núcleo común + plugins por grupo de juegos (seleccionado).
3. Una herramienta por juego (rechazado: duplicación y falta de sinergia).

## Decisión

Se adopta la **Opción B**: un núcleo común multiplataforma (GUI, mod manager, configuración, internacionalización, sistema de plugins) con extensiones tipo plugin por motor o grupo de juegos similares. El primer plugin es para **Factorio** (archivos `.zip` con `info.json`). Posteriormente se podrán agregar plugins para Unity, Unreal, Source, PAK genérico, etc.

## Consecuencias

- Positivo: aislamiento de plugins; un fallo en un plugin no afecta al núcleo; extensible sin modificar el núcleo.
- Negativo: requiere definir una interfaz de plugin estable y mantenerla versionada.

## Estado

Aceptado.
